# Benchmark v2 seed 平均三方主对照（权威结果，取代单次 run 数字）

日期：2026-10-04。代码 `aggregate_seed_avg.py`、`seed_avg_driver.sh`；结果 `artifacts/benchmark_v2_eval/seed_avg_three_way.json`、`s1_<seed>_<family>/`、`s2_<seed>/`。**本文是三方主对照的权威版本**，取代 `benchmark_v2_three_way.md` §0 的单次 run 数字（见该文档顶部的 superseded 注）。

## 为什么需要 seed 平均

`benchmark_v2_noul_fix_and_variance.md` 发现：同配置同 seed 的两次 run（pf vs pf2）因 GPU 非确定性 + per-family 早停选点噪声，结果差异达 ±0.05–0.1，score 甚至从 0.107 跌到 0.015。**单次 run 的三方数字不可靠**。故对 #1、#2 各跑 **3 个 seed**（20261001/2/3），per-family 早停 + dev 样本加大到 256（稳定选点），预算 2520 updates（已知 ≈5600），同 37 任务集。#3 frozen 确定性，复用 gen3。每任务先对 3 seed 取均值，再跨任务汇总。

## 权威结果（3 seed，mean ± SEM across tasks）

| primitive | metric | n | #1 共享打分器 | #2 任务头 | #3 frozen 生成式 |
|---|---|---|---|---|---|
| choice | accuracy | 21 | 0.486 ± 0.031 | 0.489 ± 0.031 | 0.424 |
| noul | AUROC | 7 | 0.478 ± 0.051 | **0.629 ± 0.050** | 0.522 |
| score | spearman | 9 | 0.013 ± 0.009 | 0.018 ± 0.033 | n/a(异口径) |

**逐任务（seed-mean）#1 vs #2**：#1 胜 4 / 平 23 / #2 胜 10。

**per-task run 方差（seed 间 std，跨任务平均）**：

| primitive | #1 seed-std | #2 seed-std |
|---|---|---|
| choice | 0.040 | 0.030 |
| noul | **0.087** | 0.030 |
| score | 0.064 | 0.054 |

## 判读（诚实，修正此前结论）

1. **此前"#1 共享打分器 ≥ #2 任务头"的结论不成立**——那是单次 run（bv2_pf）的乐观抽样。seed 平均后：**#2 任务头总体 ≥ #1**。
2. **noul：#2 明显且稳健地胜 #1**（0.629 vs 0.478，3 seed 一致，SEM 0.05 不重叠）。#1 的共享打分器在二元 noul 上几乎等于随机（0.478），甚至**低于 frozen #3（0.522）**；#2 的专用二分类头则学到判别力。noul 措辞修复（原始 no/yes）在端到端重训中**未能**弥补此差距。
3. **choice：#1 ≈ #2**（0.486 vs 0.489，误差内持平），二者都 > frozen #3（0.424）。
4. **score：两者都近 0**（0.013 vs 0.018，误差内持平）。#1 在 bv2_pf 单次的 0.107 是**未复现的高抽样**；seed 平均后 score 上 #1 无优势。
5. **#1 run 方差全面高于 #2**（尤其 noul 0.087 vs 0.030）：共享打分器 + 动态候选在 seed 间更不稳定；专用头更稳。
6. **两个训练臂在 choice 上都赢 frozen #3**，但 #1 在 noul 上输给 #3——即现成小 LM 的候选似然在二元判断上比训练过的共享打分器还稳。

## 对核心主张的影响

- **"共享 typed-decision scorer 无任务参数即可匹敌/超过每任务头"这一主张，在本基准、本预算下未被 seed 平均数据支持**。事实是：专用任务头在 noul 上明显更好、在 choice/score 上持平、且跨 seed 更稳定。
- 仍然成立的：①benchmark v2 + harness + 防泄漏划分是有效基础设施；②共享打分器**能机械运行**动态候选/无任务头（工程可行），但**性能不占优**；③方法论贡献——**单次 run 会严重误导，必须 seed 平均**（本工作因此推翻了自身早先结论，正是该点的证据）。
- score 上 #1 的锚点期望值 vs #2 的标量回归头：seed 平均后都近 0，此前"#1 score 明显胜"也是单次抽样，不成立。

## 局限与下一步
- 仍是小预算（2520 upd）、37 任务（cap PG=12/GUE=12）、512 窗口、单共享 checkpoint；绝对值低（choice ~0.49 近随机）。结论是"#1 不优于 #2"，非"二者都已很好"。
- noul 差距根因待查：共享打分器对二元候选的判别为何弱于专用头？可能需 noul 专用校准/温度、或候选表示改进、或更多预算。
- 若要为共享接口辩护，需在更大预算/更多数据下重测，或证明其在"动态候选/零样本新任务"上的独特能力（专用头做不到动态候选）——那是 #1 的真正卖点，本对照未测（都在已见任务上比）。
- 建议下一步：测 #1 的**零样本新任务泛化**（动态候选的真正优势）vs #2（固定头无法零样本新候选），这才是公平展现 #1 价值的对照。
